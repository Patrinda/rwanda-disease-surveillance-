    How it works

    The API sends and receives JSON at {{ base_url }}/api/v1/. Put your key in the Authorization header: Authorization: Token your-key. Reporters and officers only get data for their own district; National Administrators get everything.

    Sending a report through the API runs the same checks as the web form. When it is saved, the forecast for that disease and district is recalculated at once, and the dashboard shows the new numbers.

    Endpoints

    MethodAddressWhat it does
    GET/api/v1/status/System health and the active model.
    GET/api/v1/reports/Case reports. Filters: disease, district, from, to, limit, offset.
    POST/api/v1/reports/Send a new case report (JSON body, see below).
    GET/api/v1/predictions/Next week forecast. Filters: disease, district, min_probability.
    GET/api/v1/weather/Daily rainfall and temperature. Filters: district, days.

    Read the forecast

    Windows PowerShell

    $key = "{% if token %}{{ token.key }}{% else %}your-key{% endif %}"
Invoke-RestMethod -Headers @{Authorization="Token $key"} `
  "{{ base_url }}/api/v1/predictions/?min_probability=0.5"

    Send a new report

    Windows PowerShell

    $body = @{
  patient_name = "Aline Uwase"; age = 29; gender = "F"
  district = "Huye"; disease = "CHO"
  date_onset = "2026-10-10"; date_reported = "2026-10-11"
} | ConvertTo-Json
Invoke-RestMethod -Method Post -Headers @{Authorization="Token $key"} `
  -ContentType "application/json" -Body $body "{{ base_url }}/api/v1/reports/"

    Fields of a new report

    Required: district (name or id), disease (code, name or id), date_onset, and either patient_code of an existing patient, or patient_name, age and gender (M or F) for a new one.

    Optional: date_reported (today if left out), case_type (suspected or confirmed), status (active, recovered or deceased), notes. A wrong value returns status 400 with a list of what to fix.
